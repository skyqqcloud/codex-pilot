# Codex Pilot 2.8.0

常驻 macOS 状态栏的 Codex 账号管理工具。点击状态栏入口打开面板，查看API 输出速度、各账号剩余额度，并切换登录。开启状态栏速度显示时只显示数值和单位，关闭时显示双向箭头。没有独立主窗口或 Dock 图标。

## 使用

- **账号额度**：5 小时和 7 天的剩余百分比、进度条与重置时间。低额度只用颜色表达；过期缓存显示「待刷新」。点击刷新按钮联网更新额度。
- **切换账号**：点击账号并确认，程序先正常退出 Codex，再替换登录并重新打开。无法正常退出时会中止切换。请先结束需要保留的工作。
- **保存登录**：记录当前 Codex 登录；**添加账号**：保存原登录后打开 Codex 登录另一个账号，完成后点保存登录。添加期间不要点 Codex 的 Log out；可用「返回原账号」恢复。
- **管理账号**：拖动或点击上下箭头调整顺序；删除前确认，当前账号不能删除。
- **设置**：跟随系统／浅色／深色、状态栏显示速度、登录时启动，以及各账号自动刷新。已有自动刷新设置会沿用，每 5 分钟更新一次已启用账号。

Codex 通过 bundle id `com.openai.codex` 识别，因此磁盘上仍叫 `ChatGPT.app` 也能正确控制。

## API 输出速度

统计以已采集的完成记录为依据，不能代表采集关闭期间的全部调用。用量字段必须明确存在、为合法整数，并满足推理不超过总输出、缓存不超过输入；字段缺失或矛盾时拒绝生成测速记录，不默认成 0、不截断、不夹取。重叠流在全部结束前保持不可配对状态，失败一条不会将其余流误配给新请求；旧批次重发、迟到事件不会重开已结束的请求。过期未完成状态在处理新请求前清除。详情计时会拒绝明显缺少第一输出项的部分日志和未知输出类型，不用后面一项冒充起点。

官方运行时用带非空 `error.message` 的 `response.completed` 记录断线结束；即使没有用量字段也必须关闭失败请求，且不产生 TPS。后续重试按新的起点独立采集，避免旧失败状态把正常调用持续误判为重叠。正常 SSE 的无用量通用完成标记仍等待同次的用量完成事件；真正重叠的流继续保持不可配对状态，不能因一个失败事件而错误解除保护。失败文本不写入数值缓存。

最近 5 次平均使用筛选后最近 5 条已采集完成记录。该窗口内缺少计时的记录保留但不参与均值，既不作为 0，也不以第 6 条替换；少于 5 条有效计时时主面板显示实际有效次数，模型汇总的均值提示也提供分母数量。已采集记录以外的未观测调用不能被计入这个窗口。

非常短的输出可能集中到达，数十个 token 在不到 0.1 秒的客户端观测区间内出现时，速率可能达到数百。保留可核实的观测比值，不设置人为速度上限；这不能证明模型具有同样的持续生成速度。API 总输出还包含未单列的格式 token，因此「总输出 − 推理」也不能精确等同于用户看见的正文 token。

主面板同时显示「最近 1 次」和「最近 5 次平均」，不再按 1 分钟或 5 分钟摊薄产出。先筛选模型，再选择最近完成的请求。每次速度 =（API 总输出 token − 推理 token）÷ 对应非推理输出阶段耗时；仍含工具参数和 API 格式 token，不等于可见字符数。使用本地 Codex 日志中明确的正文/工具 output_item_added 时间至官方完成时间，不能把可能指向推理项的 TTFT 直接当作正文起点。对含推理的记录，缺少可靠起点显示「—」并保留请求用量，不估算、不设速度上限。无推理请求可使用原先记录的输出区间。最近五次请求中有可靠计时的速度取算术平均，缺失的记录不会由更早请求补位。输出阶段中的后续推理或缓冲停顿仍计入，这是客户端输出阶段速率，不是模型内部纯生成/GPU 速度。原始总输出、推理、TTFT 及遥测计时保留不改；展示所需的分段计时只在本地读取、在内存中关联，刷新时重试暂未写入的日志。

设置中的「本机测速采集」使用 Codex 官方 OpenTelemetry OTLP/HTTP JSON，将事件发送到 `127.0.0.1:45417` 的 Pilot 接收服务。由 Codex 记录的事件时间计算耗时，排除首个输出前的等待、请求间空闲和本地工具执行；不是服务端 GPU 内核测量。使用原始完成用量，不估算 token 数；缺少起点、失败、未完成或无法配对的重叠流不会生成样本。

详情页每个模型保留最近 100 次请求，列表保持固定 216pt 高度，单模型和全部模型的高度一致。按本地会话及实际发起消息分组，用户消息所在行承载该消息下本列表最早可用的一条 API 测速记录，显示其独立 TPS、模型、Fast 与时间；该调用不会再次显示为子项。后续已采集调用默认折叠，展开后缩进显示各自的模型、Fast、TPS、时间与输出摘要或工具名称。消息行注明「本组首条」，不会将未采集或已超出保留范围的历史首调用冒充为已测量数据。详情面板按内容自然增高，整个页面不滚动；请求列表和长消息区域可独立滚动。悬停使用淡灰背景，选中记录额外显示细绿色标记，下方详情同时显示本次 TPS 与完整时间。列表中当天请求仅显示时分秒，跨天保留日期；用量数字有千位分隔。点击请求查看其时间、用量与耗时，详情采用双列；刷新时保持选中记录，切换模型后默认显示该模型最近一次。最近 5 次平均的口径不变。遥测 `service_tier` 明确为 `priority` 或 `fast` 时显示小型 `Fast` 标签，表示该请求选择了 Fast 模式，不保证服务端最终执行档位。没有标识的旧样本不推断模式。

分组依据本地会话、轮次和发起消息时间标识，不按相同文字或相近时间合并；同样的文字在新的消息或不同会话中仍独立成组。请求输出仅取该次 API 起止范围内的 assistant message 和工具调用，排除推理、系统消息及工具返回；相邻调用和重叠调用边界不可靠时不猜。缺少关联信息的请求独立显示。选中后在参数下方查看完整发起消息与本次输出或工具参数，短内容按实际高度显示，长内容在单独文本区滚动。完整内容只在 UI 需要时读取本地文件，不写入 TPS 缓存。每模型保留最近 100 次请求；无可靠测速的请求仍可查看用量，但速度显示「—」。

后台调用在有明确本地证据时显示来源：「后台 · 消息建议」依据无普通会话记录的内部会话中，当前请求之前最近一条官方应用生成的消息建议指令；「自动压缩上下文」依据同会话、请求时间范围内的特殊压缩记录，其响应标识及四项用量必须完整且精确对应。只导出固定的来源标签与说明，不展示后台内部提示词、推理或压缩后的隐藏上下文。缺少证据仍显示未关联，不根据项目绑定或高低 TPS 猜测。这些后台调用继续参与现有最近一次和最近五次平均，数值与计算口径不变。

开关变更后需要重启 Codex，历史会话日志缺少完整 API 计时，无法补算。Pilot 监听样本目录变化，有新记录时更新，持续调用期间最多每 15 秒合并刷新一次；打开面板时检查最新记录，文件未变化则复用已整理结果。接收服务只绑定本机，要求随机令牌，不保存完整提示词、工具内容、账号或原始遥测，只保留模型、请求模式、数值及上述本地短句与会话标识；完整提示词遥测仍关闭。不代理 API，不发起测速请求。每个模型最多保存最近 100 个请求样本到 `~/.codex-swap/telemetry/samples.json`，文件权限 0600。退出 Pilot 会停止接收。

启用时备份 `$CODEX_HOME/config.toml` 并仅追加有标记的 `[otel]` 配置。已有自定义遥测配置时拒绝覆盖；关闭只移除 Pilot 添加的块。采集令牌保存在 `~/.codex-swap/tps-token`（0600）。账号路径和偏好设置保持原有身份。

参考 [OpenAI Docs：Observability and telemetry](https://learn.chatgpt.com/docs/config-file/config-advanced#observability-and-telemetry)。旧的用量解析保留了 [OPL Fleet Agent](https://github.com/gaofeng21cn/opl-fleet-agent) 的 Apache-2.0 授权，见 `ThirdParty/OPLFleetAgent`。

## 安装与数据

打开 `dist/Codex Pilot.dmg`，拖进「应用程序」，退出旧版后重新打开。要求 Apple Silicon、macOS 14+、Python 3（CLT 或 Homebrew）。本地包使用 ad-hoc 签名，首次打开的系统提示处理说明随 DMG 提供。

账号与额度缓存在 `~/.codex-swap/`，当前登录在 `$CODEX_HOME/auth.json`。应用包和 DMG 不包含账号数据。刷新与切换使用进程锁串行写入；网络失败保留此前额度缓存。

手动和自动刷新同时读取用量接口返回的 `plan_type`，同步账号行的套餐名称；重新打开面板优先显示已确认的服务端套餐，首次尚未获取时才回退到登录 token 的套餐声明。套餐缓存绑定账号标识，槽位换成另一账号时不复用旧套餐；接口未返回套餐或请求失败时保留同账号的最近已确认值，不根据额度推断套餐，也不改写登录 token。额度周期按服务端的秒数/分钟数字段解析；Free 的单一 30 天额度显示为 30 天，不继续固定标成 5 小时或虚构第二个周期。

更名沿用原 bundle id 与偏好设置，账号目录仍是 `~/.codex-swap/`。本机安装位置改为 `/Applications/Codex Pilot.app`。

本次升级前备份位于 `backups/latest-pre-menubar` 所指目录。回退时退出新版，将该目录下 `installed/Codex 切号.app` 复制回「应用程序」；账号数据无需回退。

## 构建与检查

```bash
bash scripts/check.sh          # 账号、采集、上下文和 Swift 统计检查，使用模拟数据
bash scripts/check.sh --live   # 再只读检查本机用量记录
bash scripts/check-scroll-layout.sh # 离屏验证详情指标常驻显示、连续重绘与滚动到底部
bash scripts/build-dmg.sh      # 生成 arm64 应用与 DMG
```

构建脚本优先使用现有 macOS 26 SDK，避开当前 CLT 27 缺少 SwiftUI 宏插件的问题。标准 XCTest 源码也保留在 `tests/telemetry`，需要完整 Xcode；上面的检查脚本可直接在 CLT 环境运行。

2.8.0 的常驻能耗优化与受控验证结果见 [能耗检查记录](docs/energy-audit-20261016.md)。

## 应急后端

应用使用内嵌后端 `Contents/Resources/codex-swap.py`，修改源码后需要重新打包。高级操作可直接运行源码：

```bash
/usr/bin/python3 backend/codex-swap.py --json
```

手动替换登录前必须自行正常退出 Codex；图形界面会自动处理退出和重开。
